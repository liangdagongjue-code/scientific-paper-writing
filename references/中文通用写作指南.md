## 一、核心方法：写一条完整的研究论证链

一篇文章不是“背景、方法、结果”几块材料的拼接，而是一条让读者自然接受的论证链：

**为什么这个问题重要 → 已有研究解决了什么 → 还剩什么具体问题 → 我们有什么关键思路 → 这个思路带来什么进展 → 有什么证据 → 因此建立了什么认识或价值。**

全文围绕同一个中心展开，但各节承担不同任务，不能反复复制同一段贡献。摘要高度概括，引言建立必要性，相关工作梳理位置，方法解释机制，结果提供证据，结论收束意义。

写之前，先用简短的话回答：

1. 本文研究的具体问题是什么？
2. 这个问题为什么值得解决？
3. 最相关的已有研究已经做到了什么？
4. 尚未解决的矛盾、条件、能力或认识是什么？
5. 我们的关键思路为什么能回应它？
6. 本文真正新增的贡献是什么？
7. 每一项贡献由什么实验、分析、证明或观察支撑？

如果某个问题没有答案，应补充资料或明确待解决内容，而不是靠更漂亮的措辞掩盖。

### 三个最重要的写作习惯

**突出有证据的优势。** 不要每讲一个贡献就立刻补一句防御性表述，冲散文章中心；同时，不能把局部收益扩大成普遍成立。该明确的条件，在影响理解的位置简洁写清楚。

**简洁不等于一味压缩。** 删除重复结论、空话和无关过程，保留解释“为什么下一步会这样做”的桥梁。压缩后读者需要自己补逻辑，就不是好的优化。

**讲机制，不堆名词。** 不是“我们使用 A、B、C 三个模块”，而是“为解决什么，需要怎样的设计，这项设计因此带来什么能力”。

## 二、迁移的是论证功能，不是固定目录

方法型实证论文可以从“引言—相关工作—问题定义—方法—实验—结论”开始设计，但不是每篇必须六节。

理论论文的核心证据可能是定理和证明；综述的贡献可能是分类框架与证据综合；观察性研究关注现象及关联；定性研究关注材料、分析过程和解释。它们都需要清楚的问题和证据，但不应被强行塞入算法实验模板。

同样，不能把以下内容当成所有论文的通用要求：固定节数、固定任务数、必须做消融、必须放运行截图、统一字体配色、删除计算开销、删除某类声明。它们取决于新研究和投稿要求。

需要区分三层：

| 层次 | 如何复用 |
|---|---|
| 通用论证原则 | 直接继承，例如递进叙事、机制解释、证据对应 |
| 个人写作偏好 | 默认采用，可按新任务调整，例如先中文审阅、结论紧凑 |
| 某篇文章的事实与决定 | 不能自动继承，例如算法名、实验数字、删节决定和图号 |

## 三、摘要：用最短的篇幅讲清研究价值

默认结构是：**研究缺口 → 本文思路或方法 → 带来的优势 → 主要发现 → 意义**。

开头尽快进入真正的问题，不从宽泛领域发展史讲起。介绍方法时，解释核心想法，而不是罗列模块名称。随后说明这个想法解决了什么困难，再概括最重要的结果，最后回到研究价值。

这五个功能不是固定五句话。通常写成一个紧凑段落；如果期刊要求结构式摘要，就把这些功能映射到相应小标题。

结果优先写总体发现，不把摘要变成实验方案清单。任务、数据集、种子、参数和所有置信区间通常不必全部出现。但也不是绝对禁用数字：如果一个效应量就是研究核心，或规范要求定量摘要，就应准确保留。

实证论文可直接用“实验表明……”进入发现；理论文章应写证明了什么，综述应写综合得到了什么认识，不能每种文章都套“实验表明”。

避免两次总结同一个意思，例如“实验表明方法有效。上述结果说明方法具有有效性。”第二句应真正推进到意义，否则删除。

## 四、引言：让研究问题自然成立

采用：**现实或理论问题 → 现有条件的矛盾 → 核心研究问题 → 已有方法与剩余不足 → 关键启发 → 本文贡献及支撑**。

开头要具体。应用例子不仅说明“在哪用”，还要说明“发生了什么困难，导致什么后果”。纯理论问题可以从知识矛盾或未解决的性质出发，不必硬编一个工业场景。

接着从大问题逐渐收束到本文真正研究的条件。某个约束如果只是本研究的选择，不能写成整个领域都必然受到的限制。

介绍已有研究时先说它们的能力，再指出还没有覆盖的条件或问题。不能把所有前人概括得很弱，以此制造创新感。研究缺口可以是新的机制解释、适用条件或证据，而不一定是“从来没人做过”。

在提出方法前先交代关键启发，让读者理解为什么会想到这个方向。最后尽量用一段顺畅地完成“提出方法—解释机制—说明优势—概括证据”。如果需要贡献列表，确保每项贡献实质不同，不只是把前一段再列一遍。

背景与他人工作应有准确引用，自己的贡献则由本文方法和证据支撑。不是每一句都必须挂引用，而是每一项知识归属要清楚。

## 五、相关工作：把研究脉络串起来

先想好读者需要理解哪些研究线，以及这些研究线为什么相互关联，再寻找对应文献。检索发现与预设不同，就修改论述，不能只保留有利于自己的材料。

按照研究问题、技术思想、假设或证据组织文献，不按作者逐条报菜名。一个段落解释一类思路，段末适当小结，再自然引向下一类。

你的默认偏好是：主要说他人研究，自己的工作在结尾简洁定位，不在每段后面都反复宣传“我们更好”。如果某处必须直接比较才能说清关系，也可以局部明确比较，而不是把“只能最后一句提自己”变成僵硬限制。

经典文献不因为旧就删，近期文献不因为新就一定引用。关键在于它是否解释概念来源或带来与本文有关的推进。正式发表的可靠原始研究优先，但未发表工作仍可能影响新颖性判断；发表状态必须真实，不能编造会议或期刊。

不把查文献的编辑过程写进论文，例如“我们对未经核实的文献进行了标注”。论文写科学内容，编辑记录另存。

## 六、问题定义与方法：先说清问题，再解释设计

### 问题定义

明确研究对象、数据、可用信息、假设、目标及评价对象。由读者熟悉的概念进入本文特定设定。不是每篇都需要独立数学章节，概念型研究也可以用清楚的分析框架完成这个功能。

重要公式采用“为什么需要 → 公式与符号 → 它意味着什么”。不能只堆公式，也不要为了看起来严谨，引入后文没有使用的假设和符号。

区分问题与解决方案：问题定义解释要解决什么以及允许用什么信息；方法解释我们怎样解决。

### 方法

采用：**设计动机 → 具体操作 → 产生的结果 → 与下一步的联系**。

先整体后局部，按实际依赖关系展开。说明哪些是新提出的，哪些是已有技术，以及新设计为什么会产生预期优势。不要让网络层数、工具名称或配置细节淹没核心思路。

理论论文需要准确说明假设、命题和证明关键；定性研究要说明解释如何从材料中得到。图、公式、伪代码和文字必须一致。

读者理解方法不可缺少的内容留在正文，长推导和完整设置可以放补充，但不能把核心限制或关键步骤藏起来。

## 七、实验、结果与讨论：用证据回答问题

先明确要验证什么，再安排相应证据。主要结果优先，随后分析机制、适用条件或其他重要问题；不是把所有跑过的东西按时间顺序写出来。

结果段可按：**验证问题 → 对比或分析方式 → 主要发现 → 关键证据 → 解释**。不固定句数，重点是证据能够回答前面的问题。

### 怎样突出优势

先说取得了什么进展，再给代表性数据和解释。大幅改善就可以明确写“大幅提升”，不必弱化成平淡的“上述变化”；但前提是效应大小和对比条件支持。

正文不逐格朗读表格，而是解释哪些差异重要、为什么重要。区分百分点与相对百分比、均值与每个个体、相关与因果、效应大小与统计显著性。

### 怎样写机制分析

方法论文的消融应说明改了什么、其他条件是否控制、结果支持什么推断。不必强迫每个组件都带来巨大收益。其他类型文章可以使用敏感性分析、反例、证据交叉核验等，而非照搬消融。

### 怎样处理范围与局限

主张决定哪些约束必须评估。如果文章主打速度，就需要相应计时证据；如果主打效率，就不能沿用别篇文章的删节决定而省略核心成本。与中心问题无关的弱点清单则不必面面俱到。

讨论解释发现的意义、机制及与文献的关系，不再重复结果表。是否单列 Discussion，由内容和领域习惯决定。

定性例子帮助解释，不替代整体证据。样本选择和展示处理影响理解时，应说清楚；不能把示意图、生成式图像或初始化截图冒充实验观测。

## 八、结论：收束贡献，提出有依据的下一步

采用：**完成了什么 → 核心价值来自哪里 → 证据建立了什么 → 意味着什么 → 还有哪些具体问题值得研究**。

结论回答引言提出的问题，但不逐字复制摘要，不罗列全部结果，更不新增正文没有建立的结论。

默认写得紧凑，能在一个段落完整表达就合为一段；不把“单段”变成所有文章的强制格式。

未来工作从真实假设、尚未解释的现象或合理的扩展中产生，不照搬参考论文的方向，也不空泛地写“探索更复杂的场景”。展望是待研究问题，不是已经实现的能力。

## 九、语言、引用和段落衔接

一段集中完成一件事：提出问题或判断，给出必要解释与证据，推进到下一步。上一句留下的问题由下一句接住，比堆砌连接词更重要。

| 逻辑关系 | 常用英文表达 | 使用条件 |
|---|---|---|
| 转折与对照 | however、whereas、in contrast | 确有相关差异，不能制造虚假的不足 |
| 推论 | therefore、thus | 前文确实支持这个结论 |
| 聚焦 | specifically、more directly | 收束到同一个问题，而非突然换话题 |
| 互补方向 | a complementary line of work | 解释它为何与当前论述有关 |
| 机制与能力 | by … thereby …、this enables … | 能力确实由前述机制带来 |
| 条件 | when、under、provided that | 条件会影响结论成立 |
| 引出方法 | building on this insight | 前面已经说明启发是什么 |

用具体动词，少用“新颖、强大、高效”的空洞组合。已经证实的事实直接说，解释性判断适度保留不确定性。“may”“can”“可能”可以用，不存在一律禁止的规则。

引用紧贴它支持的背景事实、他人方法或非平凡前提。核实原文是否真的支持该说法，不能因为关键词相近就引用。自己的结果不挂无关引用，但借用的数据、组件和概念不能省略归属。

借鉴好文章的论证组织，不复制其独特句式和大段表达。表达风格可以学习，科学贡献必须来自新研究自身。

## 十、图表与补充材料

每张图先确定要帮助读者理解什么，再选择形式。框架图突出核心机制和真实依赖，结果图展示关键比较，截图说明对象或行为。装饰不等于证据。

配色有限、语义一致、对比充分，最终版面中字体清晰可读。不固定某种字体、某套颜色或某种图标。图注交代科学解释所需信息，不逐个解释显而易见的形状；指标、误差条或特殊编码则不能因追求简短而省掉。

图表覆盖同一问题且组合更易理解时，可以同页安排；不要为了模仿别人而把不相干内容硬拼在一起。正文自然引出其研究作用，而不是单独写一句“某图展示某内容”就结束。

正文承担核心论证与必要证据；补充材料扩展完整结果、推导、设置、材料或视频。两者应一致，是否需要补充以及提交格式取决于具体期刊。伦理、披露等要求也不能继承另一篇稿件的临时决定。

## 十一、以后写新文章怎样使用

1. 提供研究问题、已有方法或发现、证据、目标读者及已知投稿要求。信息已经在项目里时，直接读取，不要求重复整理。
2. 先梳理论证主线和每节职责，再写正文。材料缺失就补查或在工作稿明确标记，不编造结论。
3. 大段新写默认先给中文确认逻辑，再完整译为英文；直接要求英文时按要求执行。
4. 翻译可以调整英语表达，不擅自压缩已认可内容，不改变数值、条件、引用与结论强度。
5. 修改按“全文逻辑—章节—段落—证据和术语—句子”顺序进行，不只做表面润色。
6. 获得入稿要求后才修改相应文件；“讨论完成”“译稿完成”“已入稿”“PDF 验证”“已投稿”分别如实报告。

以后可以直接提出：**“按照这套通用论文写作 skill，先梳理本文的研究问题、创新点和证据，再写中文引言。”**

最终检查不在于是否长得像某篇参考论文，而在于：读者能否清楚回答——**问题是什么，为什么仍需研究，我们新增了什么，证据在哪里，这项进展意味着什么。**
